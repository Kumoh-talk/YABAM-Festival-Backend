# 결제 (Payment) 유스케이스

> 이 문서는 구현 코드 기준의 실제 유스케이스 명세입니다.
> 도메인 규칙 변경 시 반드시 함께 수정하세요.

---

### 결제 승인

- **고객은 토스페이먼츠로 결제하고 영수증을 자동 정산할 수 있다**
    - 결제 위젯에서 결제 완료 후 paymentKey, orderId(=receiptId), amount를 서버에 전달한다.
    - 서버는 토스페이먼츠 결제 승인 API를 호출하여 결제를 확정한다.
    - 결제 금액이 영수증의 테이블 점유비와 일치해야 한다.
    - 결제 승인 성공 시 영수증이 자동으로 정산(isAdjusted = true) 처리된다.
    - 테이블 활성화 상태가 비활성화로 변경된다.
    - 이미 정산된 영수증은 결제할 수 없다.
    - 인증 없이도 가능하다.

---

### 결제 취소

- **점주는 결제를 취소(환불)할 수 있다**
    - paymentKey와 취소 사유로 결제를 취소할 수 있다.
    - 서버는 토스페이먼츠 결제 취소 API를 호출한다.
    - 본인 가게의 영수증에 대한 결제만 취소할 수 있다.
    - 점주(`ROLE_OWNER`) 권한이 필요하다.

---

### 결제 정보 조회

- **누구나 영수증의 결제 정보를 조회할 수 있다**
    - receiptId로 해당 영수증의 결제 정보를 조회할 수 있다.
    - 결제 내역이 없는 영수증은 null을 반환한다.
    - 인증 없이도 가능하다.

---

### 영업별 결제 목록 조회

- **점주는 특정 영업의 결제 내역 목록을 조회할 수 있다**
    - saleId로 해당 영업에 속한 모든 결제 목록을 조회할 수 있다.
    - 결제 내역이 없는 경우 빈 목록을 반환한다.
    - 점주(`ROLE_OWNER`) 권한이 필요하다.

---

### 토스페이먼츠 실시간 결제 상태 조회

- **점주는 토스페이먼츠에서 결제 상태를 실시간으로 조회할 수 있다**
    - paymentKey로 토스페이먼츠 서버에서 직접 결제 정보를 조회한다.
    - 로컬 DB와 외부 PG사 데이터 간 대사(reconciliation)에 사용한다.
    - 점주(`ROLE_OWNER`) 권한이 필요하다.

---

### 웹훅 처리

- **서버는 토스페이먼츠 웹훅으로 결제 상태를 비동기 동기화할 수 있다**
    - `PAYMENT_STATUS_CHANGED` 이벤트 수신 시 로컬 결제 상태를 업데이트한다.
    - HMAC-SHA256 서명 검증을 통해 요청의 신뢰성을 확인한다.
    - 서명이 유효하지 않으면 401 응답을 반환한다.
    - `CANCELED`, `PARTIAL_CANCELED` 상태로만 동기화한다.
    - 인증 없이도 가능하다 (서명으로 검증).
