# 결제 (Payment) 유스케이스

> 이 문서는 구현 코드 기준의 실제 유스케이스 명세입니다.
> 도메인 규칙 변경 시 반드시 함께 수정하세요.

---

### 결제 승인

- **고객은 토스페이먼츠로 결제하고 영수증을 자동 정산할 수 있다**
    - 결제 위젯에서 결제 완료 후 paymentKey, orderId(=receiptId), amount를 서버에 전달한다.
    - 서버는 비관적 잠금과 선점 레코드 패턴으로 동시 결제 요청을 방지하며 3단계로 처리한다.
        1. 검증·잠금·선점 레코드 저장 (write 트랜잭션): 영수증 행을 PESSIMISTIC_WRITE로 잠금 후 `IN_PROGRESS` 선점 레코드을 저장하고 커밋한다. 이후 중복 요청은 선점 레코드을 감지해 즉시 차단된다.
        2. 외부 API 호출 (트랜잭션 없음): 토스페이먼츠 confirm API를 호출한다.
        3. 최종 저장·정산 (REQUIRES_NEW 트랜잭션): 선점 레코드 상태를 실제 결과로 업데이트하고 정산한다.
    - 결제 금액이 영수증의 테이블 점유비와 일치해야 한다.
    - 카드 결제의 경우 승인 즉시 영수증이 자동으로 정산(`isAdjusted = true`) 처리되고 테이블이 비활성화된다.
    - 가상계좌 결제의 경우 승인 시점에는 `WAITING_FOR_DEPOSIT` 상태로만 저장되고 정산은 입금 완료 웹훅 수신 후 처리된다.
    - 이미 정산된 영수증은 결제할 수 없다.
    - `IN_PROGRESS`, `DONE`, `WAITING_FOR_DEPOSIT`, `CANCELED`, `PARTIAL_CANCELED` 상태의 결제가 존재하는 영수증은 재결제할 수 없다.
    - `ABORTED` 상태(이전 시도 실패)의 선점 레코드이 있는 경우 선점 레코드을 삭제하고 재시도를 허용한다.
    - PG 호출 또는 저장 실패 시 선점 레코드을 `ABORTED`로 마킹한다.
    - 저장 실패 시 토스페이먼츠에 자동 보상 취소를 요청한다 (DONE 상태인 경우).
    - 타임아웃 발생 시 토스페이먼츠에서 현재 결제 상태를 재확인하여 처리한다.
    - 인증 없이도 가능하다.

---

### 결제 취소

- **점주는 결제를 취소(환불)할 수 있다**
    - paymentKey와 취소 사유로 결제를 취소할 수 있다.
    - `cancelAmount` 지정 시 부분 취소, 미지정 시 전액 취소한다.
    - 서버는 토스페이먼츠 결제 취소 API를 호출한다.
    - 본인 가게의 영수증에 대한 결제만 취소할 수 있다.
    - 이미 취소된 결제는 재취소할 수 없다.
    - 점주(`ROLE_OWNER`) 권한이 필요하다.

---

### 결제 정보 조회

- **누구나 영수증의 결제 정보를 조회할 수 있다**
    - receiptId로 해당 영수증의 결제 정보를 조회할 수 있다.
    - 결제 내역이 없는 영수증은 null을 반환한다.
    - 인증 없이도 가능하다.

---

### 영업별 결제 목록 조회

- **점주는 특정 영업의 결제 내역 목록을 조회할 수 있다**
    - saleId로 해당 영업에 속한 모든 결제 목록을 조회할 수 있다.
    - 결제 내역이 없는 경우 빈 목록을 반환한다.
    - 점주(`ROLE_OWNER`) 권한이 필요하다.

---

### 토스페이먼츠 실시간 결제 상태 조회

- **점주는 토스페이먼츠에서 결제 상태를 실시간으로 조회할 수 있다**
    - paymentKey로 토스페이먼츠 서버에서 직접 결제 정보를 조회한다.
    - 로컬 DB와 외부 PG사 데이터 간 대사(reconciliation)에 사용한다.
    - 점주(`ROLE_OWNER`) 권한이 필요하다.

---

### 웹훅 처리

- **서버는 토스페이먼츠 웹훅으로 결제 상태를 비동기 동기화할 수 있다**
    - `PAYMENT_STATUS_CHANGED` 이벤트 수신 시 로컬 결제 상태를 업데이트한다.
    - HMAC-SHA256 서명 검증을 통해 요청의 신뢰성을 확인한다.
    - 서명이 유효하지 않으면 401 응답을 반환한다.
    - `CANCELED`, `PARTIAL_CANCELED` 상태 수신 시 결제 상태를 동기화한다.
    - 가상계좌 결제의 경우 `WAITING_FOR_DEPOSIT → DONE` 전환 시 영수증 자동 정산 및 테이블 비활성화를 처리한다.
    - 이미 정산된 영수증은 중복 정산하지 않는다.
    - 인증 없이도 가능하다 (서명으로 검증).
