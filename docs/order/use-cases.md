# 주문 유스케이스

> 이 문서는 구현 코드 기준의 실제 유스케이스 명세입니다.
> 도메인 규칙 변경 시 반드시 함께 수정하세요.

---

## 장바구니

- **고객은 장바구니에 메뉴를 추가할 수 있다**
    - 메뉴 ID와 수량(최소 1개)으로 장바구니에 담을 수 있다.
    - 동일 메뉴가 이미 담겨 있으면 수량을 덮어씌운다(Upsert).
    - 인증 없이도 가능하다.

- **고객은 장바구니에서 메뉴를 삭제할 수 있다**
    - 영수증 ID와 메뉴 ID로 특정 메뉴를 장바구니에서 제거할 수 있다.
    - 인증 없이도 가능하다.

- **고객은 장바구니 정보를 조회할 수 있다**
    - 영수증 ID로 현재 장바구니에 담긴 메뉴 목록을 조회할 수 있다.
    - 담긴 메뉴가 없으면 빈 장바구니를 반환한다.
    - 인증 없이도 가능하다.

---

## 주문 세션 (동시성 제어)

- **고객은 주문 전 주문 세션에 진입할 수 있다**
    - 장바구니 → 주문 전환 시 세션 토큰(UUID)을 발급받는다.
    - 영수증 단위로 동시에 하나의 세션만 존재할 수 있다.
    - 발급받은 토큰은 주문 생성 요청 시 `X-Order-Session-Token` 헤더에 담아 사용한다.
    - 인증 없이도 가능하다.

- **고객은 주문 세션을 취소할 수 있다**
    - `X-Order-Session-Token` 헤더를 포함해 세션을 명시적으로 취소할 수 있다.
    - 인증 없이도 가능하다.

---

## 주문 생성

- **고객은 장바구니에 담긴 메뉴로 주문을 생성할 수 있다**
    - 주문 세션 토큰(`X-Order-Session-Token`)이 있어야 주문을 생성할 수 있다.
    - 장바구니를 삭제하지 않고 재활용한다.
    - 인증 없이도 가능하다.

- **점주는 메뉴를 직접 지정해 주문을 생성할 수 있다 (직접 주문)**
    - 메뉴 ID와 수량 목록으로 직접 주문을 생성할 수 있다.
    - 점주(`ROLE_OWNER`) 권한이 필요하다.

- **점주는 커스텀 주문을 생성할 수 있다**
    - 메뉴 없이 주문 금액과 설명만으로 주문을 생성할 수 있다(예: 서비스 항목).
    - 주문 금액과 설명은 필수값이다.
    - 점주(`ROLE_OWNER`) 권한이 필요하다.

## 주문 수정 / 삭제

- **점주는 커스텀 주문을 수정할 수 있다**
    - 커스텀 주문의 금액과 설명을 수정할 수 있다.
    - 본인 가게의 주문만 수정할 수 있다.

- **점주는 주문을 삭제할 수 있다**
    - 본인 가게의 주문만 삭제할 수 있다.

## 주문 상태 전환

- **점주와 고객은 주문 상태를 변환할 수 있다**
    - 주문 상태: 주문(ORDERED) / 접수(RECEIVED) / 취소(CANCELED) / 완료(COMPLETED)
        - ORDERED(주문)
            - **점주는 "주문" 상태를 접수(RECEIVED) 또는 취소(CANCELED) 상태로 변환할 수 있다**
              → 주문이 접수 상태로 변경되면 해당 주문의 모든 주문 메뉴가 조리중(COOKING)으로 자동 전환된다.
            - **고객은 "주문" 상태를 취소(CANCELED) 상태로만 변환할 수 있다**
        - RECEIVED(접수)
            - **점주는 "접수" 상태를 취소(CANCELED) 상태로 변환할 수 있다**
        - CANCELED(취소)
            - **점주는 "취소" 상태를 접수(RECEIVED) 상태로 재변환할 수 있다**
        - COMPLETED(완료)
            - **점주는 "완료" 상태를 취소(CANCELED) 또는 접수(RECEIVED) 상태로 변환할 수 있다**

---

## 주문 조회

- **누구나 영수증의 주문 목록을 조회할 수 있다**
    - 영수증 ID로 해당 영수증의 전체 주문과 주문 메뉴를 조회할 수 있다.
    - 인증 없이도 가능하다.

- **누구나 주문 상세 정보를 조회할 수 있다**
    - 주문 ID로 단건 주문과 주문 메뉴를 조회할 수 있다.
    - 인증 없이도 가능하다.

- **점주는 영업별 주문 목록을 조회할 수 있다**
    - `saleId`와 주문 상태 목록(`orderStatuses`)으로 필터링하여 커서 기반 슬라이스로 조회할 수 있다.
    - 본인 가게의 영업에 대해서만 조회할 수 있다.

---

## 주문 메뉴 상태 전환

- **점주와 고객은 주문 메뉴 상태를 변환할 수 있다**
    - 주문 메뉴 상태: 주문(ORDERED) / 조리중(COOKING) / 취소(CANCELED) / 완료(COMPLETED)
        - ORDERED(주문)
            - **점주는 "주문" 상태를 조리중(COOKING), 취소(CANCELED), 완료(COMPLETED) 상태로 변환할 수 있다**
            - **고객은 "주문" 상태를 취소(CANCELED) 상태로만 변환할 수 있다**
        - COOKING(조리중)
            - **점주는 "조리중" 상태를 취소(CANCELED) 또는 완료(COMPLETED) 상태로 변환할 수 있다**
        - CANCELED(취소)
            - **점주는 "취소" 상태를 조리중(COOKING) 상태로 변환할 수 있다**
        - COMPLETED(완료)
            - **점주는 "완료" 상태를 조리중(COOKING) 상태로 변환할 수 있다**
              → 모든 주문 메뉴가 완료(COMPLETED) 또는 취소(CANCELED) 상태가 되면 주문 상태가 자동으로 완료(COMPLETED)로 전환된다.

## 주문 메뉴 추가 / 삭제 / 수량 수정

- **점주는 주문에 주문 메뉴를 추가할 수 있다**
    - 기존 주문에 메뉴 ID와 수량으로 주문 메뉴를 추가할 수 있다.
    - 본인 가게의 주문에만 추가할 수 있다.

- **점주는 주문 메뉴를 삭제할 수 있다**
    - 본인 가게의 주문 메뉴만 삭제할 수 있다.

- **점주는 주문 메뉴의 수량을 수정할 수 있다**
    - 수량은 최소 1 이상이어야 한다.
    - 본인 가게의 주문 메뉴만 수정할 수 있다.

- **점주는 주문 메뉴의 조리 완료 수량을 수정할 수 있다**
    - 완료 수량은 최소 0 이상이어야 한다.
    - 본인 가게의 주문 메뉴만 수정할 수 있다.
