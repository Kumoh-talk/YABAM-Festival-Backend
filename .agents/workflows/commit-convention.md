# YABAM 프로젝트 Git 커밋 컨벤션 (Commit Convention)

본 문서는 YABAM 프로젝트에서 `antigravity` 에이전트 및 모든 기여자가 반드시 따라야 할 **커밋 메시지 규칙**을 정의합니다.
프로젝트에 `commitlint` 및 `husky`가 적용되어 있으므로 규칙 위반 시 커밋이 거부됩니다.

## 1. 커밋 메시지 형식

```
<type>: <한국어 설명>
```

### 필수 규칙
- **scope(스코프)는 사용하지 않습니다.** (`scope-empty: always` 적용됨)
- **설명(description)은 반드시 한국어로 작성합니다.**
- 헤더 전체 길이는 **100자 이내**로 제한합니다.
- 본문(body)을 작성할 경우 한 줄당 **100자 이내**로 제한합니다.

### type 종류 (허용된 태그만 사용 가능)

| type | 사용 시점 | 예시 |
|---|---|---|
| `feat` | 새로운 기능 추가 | `feat: 주문 SSE 실시간 알림 기능 추가` |
| `fix` | 버그 수정 | `fix: 주문 조회 시 N+1 쿼리 발생 문제 해결` |
| `docs` | 문서 수정 (코드 변경 없음) | `docs: 워크플로우 가이드 문서 작성` |
| `style` | 코드 포맷팅, 세미콜론 누락 등 (로직 변경 없음) | `style: 불필요한 import 정리` |
| `refactor` | 기능 변경 없이 코드 구조 개선 | `refactor: 주문 조회 쿼리 2단계 분리로 리팩터링` |
| `test` | 테스트 코드 추가 또는 수정 | `test: OrderMenuRepository 단위 테스트 추가` |
| `chore` | 빌드, 설정, 패키지 등 기타 변경 | `chore: Gradle JDK 17 설정 추가` |

## 2. 커밋 분리 원칙

하나의 커밋에 여러 성격의 변경사항을 섞지 않습니다. 아래와 같이 **목적별로 분리**합니다.

- ✅ 설정 변경 → `chore` 커밋
- ✅ 프로덕션 코드 리팩터링/버그 수정 → `refactor` 또는 `fix` 커밋
- ✅ 테스트 코드 추가 → `test` 커밋
- ✅ 문서 추가/수정 → `docs` 커밋
- ❌ 설정 변경 + 코드 수정 + 테스트를 하나의 커밋에 몰아넣기

## 3. 커밋 시 주의사항

- `--no-verify` 플래그는 린트/빌드 설정이 제거된 현재 환경에서만 허용합니다. 향후 CI가 복구되면 사용을 자제합니다.
- 임시 파일(`test_result_*.txt`, `build_err.log` 등)은 절대 커밋에 포함하지 않습니다.
- `.claude/`, `.plan/`, `.sisyphus/` 등 에이전트/계획 파일은 별도 관리하며 프로덕션 커밋에 섞지 않습니다.
